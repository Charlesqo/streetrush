# 主直道路面：完整链核查与交付范围

2026-09-20。针对“当前渲染到底缺什么”，重新读取实际入口与shader。本记录把存在、缺失和候选分开；未将以下尚未实施的材质方案称为完成。

## 已接入的基础链

`真实BaseColor/Normal/ORM → 三样本平移混合 → MeshStandardMaterial → 太阳直射+阴影+HDR/PMREM环境+半球补光 → 线性HDR目标 → GTAO → ACES/输出色彩转换 → 页面显示`

基础法线、粗糙度、AO、太阳、环境反射、阴影和输出转换都有代码接线。上轮试验只改了道路DFG积分，不是把缺失的整套反射系统补上。也没有把扫描高度、局部可见性、法线统计过滤或道路联合状态层一起实现。

## 当前确实存在的缺口

| 环节 | 本次源码事实 | 完整道路方案应补的工作 |
|---|---|---|
| 扫描素材校准 | 加载BaseColor、Normal、ORM；主材质roughness=1乘贴图；80%去色，Fresh底色另乘1.65 | 根据道路参考与来源尺度确定主体/边缘用途，复核底色、粗糙度与法线关系；把临时调色与物理输入区分 |
| 近处微结构 | 主路是平面条带；没有接Bump/Displacement，没有高度感知的局部可见性 | 需要有依据的高度/几何参照，按可见范围表达局部遮挡及必要的深度；POM或小几何是实现选项，不是全场必开项 |
| 直接光微遮蔽 | aoMap只进入间接漫射和环境镜面遮蔽；现有GTAO看场景深度，普通normal map没有颗粒深度 | 区分颗粒邻近挡光与已有GGX Smith/场景阴影；不能把当前AO直接再乘一次当完成 |
| 距离过滤 | 普通纹理mip、各向异性采样；Three的geometryRoughness使用未扰动法线导数，不能替代扫描normal map方差过滤 | 预处理可靠的法线统计/反射响应，建立近中远连续表示；验收驾驶距离的反射与运动稳定性，不能靠关mip或全局拉normal强度 |
| 反重复 | 三样本全通道线性混合，立方权重；有已测的额外局部变化损失 | 把微结构与中尺度变化分工，维持多通道对应，并检查清晰度包络/格子；普通重复采样也只能作为对照 |
| 整条道路状态 | 一套底材覆盖主直道；已有边缘尘土/补片，弯道胶痕用透明Basic材质 | 按真实位置组织磨光、材料批次、接缝、修补、积尘；覆盖权重同时控制颜色、粗糙度、法线/高度，避免仅加黑色污渍 |
| 灯光与显示 | 太阳、HDR、PMREM和ACES存在；实际检查模式还叠着菜单渐变 | 固定真实相机/曝光/天空，排除显示遮罩干扰后比较；现有光照有近似边界，但未证实缺SSR/光追是主因 |

扫描法线会改变受光方向，但不会让相邻颗粒真的挡住光。太阳阴影图默认112m覆盖/2048分辨率，空间采样量级约5.5cm，不能自动恢复毫米级孔隙阴影。当前GTAO也不知道平面贴图里的毫米深度。两者都存在，不等于微结构遮挡已经存在。

同时，普通roughness本来就在表达更小尺度的微表面，因此新微遮蔽/方差处理必须避免重复计算。前轮跨光角实验已证明统一AO代理对Fresh可能更差；这项仍须分材质验证，不具备现成可直接推广的系数。

## 本轮发现并修复的确定错误

检查模式只隐藏menu/HUD/loading，没有处理 `body::after`。实页读取确认：

- `body.className = circuit-art-camera`。
- 页面仍应用菜单线性渐变：左端alpha=.58，38%处alpha=.28，72%处透明，另有径向暗角。
- 它在画布之上，z-index=2，因此最终截图同时包含渲染结果与菜单压暗。不能据此直接用屏幕颜色校准路面或太阳。

已在 `src/style.css` 增加仅针对检查模式的 `body.circuit-art-camera::after { background: none; }`。实页更新后读取backgroundImage为none，未捕获浏览器error/warn。没有更改太阳、曝光、材质或普通菜单/比赛的样式规则。

这个修复只清理观察条件，不构成新的道路材质提升。上一轮同机位A/B仍是在同一遮罩下比较，切换恢复的证据仍成立；但那些最终截图不应称为纯renderer输出。上轮独立GPU线性AOV不受CSS影响。

## “做完整”的具体交付定义

交付对象应当是一套主直道道路材质：从输入校准、微结构表示、过滤和反重复，到按位置混合的道路状态，再到同一游戏光照下的最终画面。近景和驾驶距离使用连续的表示；铺回整段641m主直道；保留原方案作为一键整体对照。

完成判断包括：近处存在可信的颗粒受光/遮蔽差异；驾驶距离保留合理的平均反射与层次；移动时无明显闪烁/LOD跳变；重复图案明显减少；路肩、修补、积尘位置合理且材质响应一致。每项必须有实际画面对照，不能以材质文件存在或平均亮度上升代替。

没有证据要求先换引擎、开启全部重型后处理、给全场铺高模或同时上SSR/光追。基础PBR链已有；目前尚未做完的是道路专用的材质表达、过滤和内容组织。仅修改DFG不满足上述交付定义。

## 源码定位

- `src/dev-straight-art.js`：素材输入、两种底材、路肩与局部装饰。
- `src/scan-surface-sampling.js`：三样本混合与临时调色。
- `src/track.js`的createStrip：实际道路几何。
- `node_modules/three/src/renderers/shaders/ShaderChunk/aomap_fragment.glsl.js`：AO影响范围。
- `node_modules/three/src/renderers/shaders/ShaderChunk/lights_physical_fragment.glsl.js`：基底法线导数roughness补偿。
- `src/track-surface-detail.js`：Basic胶痕层。
- `src/rendering.js`、`src/render-pipeline.js`：场景光照与后处理。
- `src/style.css`、`src/dev-circuit-review.js`：页面覆盖层与检查模式。
