# 当前两套真实沥青素材与采样：专项核查

2026-09-16。只读原始下载 ZIP、当前运行用图片及相关源代码；没有执行外部研究包代码，没有改 src、原 ZIP 或生成替代素材。以下为实际素材统计和 CPU 受控算子实验，不是完整游戏画面归因。

## 核心判断

1. 现在不能说“没有细节数据”“法线必然反了”或“没有反射”。Fine 有很强的细小法线变化，且与同包 Bump 的方向高度一致。但大部分信号集中在很短的波长，驾驶尺度下普通 mip 会迅速把方向平均到接近平面。
2. 当前反重复混合确有代价，但本次实际扫描样本中，额外的颜色/roughness 标准差损失约 11–15%，不是全图统一损失 42%。不能把它当作大多数损失的已证实来源。
3. “细小、局部、随角度变化的反射不足”与“反射能量太少”是不同问题。受控直接光模型中，Fine 的 mip/平均法线可使反射更均匀、平均值反而提高。这需要与项目真实 GPU 分项结果合并判断，不能继续只靠增光或降 roughness。
4. 这两套素材的颜色、法线、roughness 联合关系不同；把两者调成相近灰色，不会使它们成为同一种材质。Fine 在元数据中就是 old/worn/weathered，Fresh 是 new。

## 核查范围与可复算资料

- 实际输入：`scratch/straight-art-20260916/assets/{asphalt,fresh}/{BaseColor,Normal,Roughness,AO}.jpg`，以及 ORM；两份原始 4K ZIP 中 JSON、Bump、Gloss、Specular，Fresh 另有 Displacement。
- 两套共 8 张主要 JPG 均为 4096×4096；准备文件与 ZIP 对应条目逐字节一致，未发现本项目导出时损坏或降质。
- ZIP JSON 列出的 maps 多是库内 8K 条目，不能把这些条目里的 min/max、averageColor、resolution 当作下载 4K 实测。本次使用实际 4K 像素。
- `analyze_materials.py` → `asphalt-measurements.json`、`fresh-measurements.json`、`method.json`。
- `analyze_spectrum.py` → `spectral-measurements.json`。
- `analyze_weights.py` → `blend-weight-conditioned.json`。
- `analyze_auxiliary.py` → `auxiliary-map-checks.json`。

## 1. 输入、法线方向与异常像素

| 项目 | Fine | Fresh |
|---|---:|---:|
| 实际物理扫描面积 | 3×3 m | 2×2 m |
| 当前 4K 纹素间距 | 0.732 mm | 0.488 mm |
| JSON 的 height 字段 | 9 mm | 27 mm |
| 源像素归一化后的平均法线倾角（1/16规则取样） | 50.58° | 15.81° |
| 倾角超过 60° 的全图比例 | 36.68% | 0.071% |
| 解码后 Z<0 | 430/16,777,216，约 0.00256% | 0 |
| 解码前向量长度均值/标准差 | 0.980 / 0.144 | 1.001 / 0.0154 |

Fine 的 430 个负 Z 像素分散在图内，不是一大片反向区域；不足以解释整个路面发平。Fine 的原始向量长度波动确实大：24.43% 小于 0.9、18.51% 大于 1.1。当前 shader 会归一化，但这也意味着不能拿原向量长度直接套 Toksvig 就称作真实未解析方差。源文件自身不是严格单位法线集合，需要先明确制作/导出过程；本次没有证明是哪一步导致长度波动。

两套 JSON 将 Normal 标为 Linear，但没有明确 OpenGL/DirectX/+Y/-Y 字段。进行了同包 Bump 的方向一致性检查：在图像 x 向右、y 向下、height 越大越高的约定下，+Y 法线应与 `(-dB/dx,+dB/dImageY)` 同向。1 像素中心差分得到：

| 同向相关系数 | Fine | Fresh |
|---|---:|---:|
| Normal.x 与 -dB/dx | +0.855 | +0.633 |
| Normal.y 与 +dB/dImageY | +0.856 | +0.612 |

这支持两套都符合常见 +Y 约定，且与当前 HTML Image flipY + tangent-space normal 用法方向相容。它不是官方约定声明，也不能独立证明项目 TBN；但“先翻绿通道试着修”目前没有强证据。Fine 的相关性到 4 像素差分已近零，Fresh 到 8 像素仍有正相关，也提示二者细节频率显著不同。

两套当前 JPEG 均为 4:4:4，没有现时 JPEG 色度子采样；量化表元素范围 1–2，属于很轻的本次压缩。不能据此排除更早的制作/缩放损失，也不应把“用了 JPG”直接当主因。

## 2. 实际频率：Fine 的强法线主要有多细

对完整 4K Normal.x / Normal.y 去 DC 后做周期 DFT，用物理扫描尺寸换算波长，统计信号功率：

| 波长范围 | Fine 法线 X/Y 功率比例 | Fresh 法线 X/Y 功率比例 |
|---|---:|---:|
| 小于 5 mm | 85.3% / 84.8% | 41.1% / 38.3% |
| 小于 10 mm | 98.35% / 98.31% | 69.3% / 67.0% |
| 小于 20 mm | 99.74% / 99.76% | 92.1% / 91.4% |

这是纹理信号波长，不等于石子直径或物理粗糙度参数；无窗周期 FFT 可能受接缝泄漏影响。即使保留这个边界，Fine 的法线主要集中在毫米尺度是非常明确的。

常规逐级 2×2 箱滤波 mip，再做与普通采样相同的双线性插值、归一化，随机 UV 18 万点的平均倾角如下；尚未启用随机混合：

| mip 级别 | Fine 有效 texel / 倾角 | Fresh 有效 texel / 倾角 |
|---|---|---|
| LOD 0 | 0.732 mm / 44.39° | 0.488 mm / 15.41° |
| LOD 2 | 2.93 mm / 14.49° | 1.95 mm / 10.99° |
| LOD 4 | 11.72 mm / 3.23° | 7.81 mm / 4.16° |
| LOD 6 | 46.88 mm / 2.07° | 31.25 mm / 1.09° |

这是受控 CPU mip，不是读取浏览器实际选中的 LOD/AF 足迹。约 10 m 前方、当前 866px 高/FOV58/相机高1.7m 的估算像素足迹约横向13mm、纵向76mm；足以平均很多 Fine 法线。由此得到的合理问题是“消失的方向分布怎样交给反射模型”，不是“把 normalScale 加大能否把所有远处石粒重新画出来”。

## 3. 粗糙度与颜色是否对应

| 实测 | Fine | Fresh |
|---|---:|---:|
| roughness 均值 | 0.8365 | 0.8095 |
| roughness 标准差 | 0.0325 | 0.0773 |
| roughness<0.6 的面积 | 0.170% | 0.253% |
| roughness<0.7 的面积 | 0.784% | 8.58% |
| 线性底色亮度与 roughness 相关系数 | -0.901 | +0.442 |
| 最暗 20% 像素的 roughness 均值 | 0.866 | 0.746 |
| 最亮 20% 像素的 roughness 均值 | 0.792 | 0.871 |

相关与分组数据来自对齐的每4像素网格，约104万点；这是源图统计，不等于屏幕可见贡献。Fine 较亮区域较光滑，Fresh 较亮区域反而整体更粗糙。不能给两张图套相同的“亮颗粒自动降低粗糙度”规则，也不能从这些相关值单独判断任一套错误。

Fine 的局部低 roughness 面积很小；它适合宽柔反射的响应，不直接包含大量尖亮颗粒。强 normal 并不自动补足低 roughness 的稀疏切面响应。

源线性亮度均值 Fine≈0.0400、Fresh≈0.01845。Fresh 的现行 gain=1.65 后约0.0304，仍比 Fine 低约24%；80%去饱和保留线性亮度。这个美术补偿只改 diffuse 底色，不会按相同比例改变非金属 F0。两种材质颜色收敛后，镜面/漫反射相对关系依然不同。

## 4. 当前随机混合对真实纹理的影响

复现现行三角格、三次幂归一化权重、共同平移，在实际 641×14m UV 域均匀取18万点。每个源通道共同偏移，BaseColor在线性空间混合，Normal解码并在最终归一化。CPU hash使用双精度 sin，不保证与 GPU hash 逐像素同图；用来衡量该策略的统计影响。

全通道混合相对普通单样本双线性读取：

| 项目 | Fine | Fresh |
|---|---:|---:|
| LOD0 亮度标准差保留 | 88.8% | 86.5% |
| LOD0 roughness 标准差保留 | 86.7% | 86.7% |
| LOD4 亮度标准差保留 | 86.3% | 86.3% |
| LOD4 roughness 标准差保留 | 86.5% | 86.5% |
| LOD0 法线平均倾角，混合前→后 | 44.39°→39.84° | 15.41°→13.37° |
| LOD4 法线平均倾角，混合前→后 | 3.23°→2.93° | 4.16°→3.59° |

因此，报告中的等权点57.7%标准差公式成立，但不代表当前三次幂权重整张路面只有57.7%对比。Fine 从 LOD0 到 LOD4 的方向变化大幅减少已经发生在普通过滤阶段；随机混合是额外影响。

### 重复可能来自“清晰度分布”，不只是原图颜色重复

另取60万点，按 `Σw²` 分组：强混合区（0.333–0.45）的亮度标准差保留 Fine约64%、Fresh约58%；近单样本区（0.9–1）分别约99%、98%。两组平均亮度很接近。也就是说，同一重复格中可规律出现“更糊/更清晰”的区域，即使平均颜色没有方块边界。

这个格子的物理晶格向量是 Fine `(3,0)m` 与 `(1.5,2.598)m`，Fresh `(2,0)m` 与 `(1,1.732)m`。它是三角格，不应把用户看到的所有方块直接断言成它；下一步应在真实画面显示权重/样本ID，核对位置相关性。

原扫描本身还残留低频变化：Fine 的0.375m方块平均亮度CV约3.44%，0.75m约2.19%；Fresh的0.25m约2.04%，0.5m约1.30%。近处微颗粒被缩小后，这些低频差异会更突出。当前方案打散位置，但不会自动创造独一条道路的施工/磨损组织。

## 5. 多角直接反射：能量并未被一概“吃掉”

用实际通道复现 Three r180 Standard 的直接光分支：F0=0.04，alpha=r²，相关 Smith GGX、同版 Schlick 近似，平面 TBN，unit directional radiance。五组光/视角包含48°太阳、10°视角的前/侧/后方向，10°低太阳镜像方向，以及30°视角。没有 IBL、AO、阴影、雾、显示映射，不声称对应完整游戏。

以48°太阳/10°视角/前向为例：

- Fine LOD0：随机混合使镜面均值上升约10.5%，镜面CV从0.655到0.584；LOD4均值变化约+0.058%，CV从0.0374到0.0322。
- Fresh LOD0：镜面均值约+2.0%，CV从0.402到0.344；LOD4均值约+0.035%，CV从0.1348到0.1159。
- 其余角度也没有“随机混合总是压低镜面能量”的现象。不同角度的响应变化方向不同，而对比下降更稳定。

进一步做“先在源纹素着色再按足迹平均”对比“先平均C/N/R，再着色”：Fine在128×16纹素箱式足迹下，五组角度的镜面平均值偏差约+19%至+144%；Fresh约-1%至+12%。这证明 Fine 对过滤顺序更敏感，也说明平均法线后的光滑、均匀响应不等于“没有反射”。

**严格边界：** 上述先着色再平均只是同一当前shader的空间积分参考，不是实际沥青物理真值。源 normal 本身幅度是否合理、roughness已含哪些尺度、微面遮蔽/可见性是否正确均未辨识；不能将这些百分比解释为游戏实际误差或直接增加对应roughness补偿。真实GPU使用的椭圆/各向异性过滤也不等于这些箱式足迹。

## 6. 同包中未使用的 Specular/Gloss 信息

当前准备脚本没有加载 Bump、Gloss、Specular 或 Displacement；MeshStandard的非金属F0固定0.04。ZIP确实有Specular图，不是没有反射信息可研究。

按元数据的sRGB声明解码，Specular灰度均值Fine≈0.0256、Fresh≈0.0282，存在空间变化。但是没有源导出工作流证明它们可直接视为实测F0；也可能含旧workflow修正。不能用“把漏掉的Specular图接上”作为立即处方——均值还低于当前0.04，不会自动增加整体亮度。应先看它与骨料、孔隙、AO的关系，再决定是否有值得保留的材质分区信息。

Gloss与1−Roughness的像素平均绝对差Fine约0.0137、Fresh约0.0117，并非逐像素严格互补。不能未经验证随意互换。

## 对项目下一步的判断

已读取主任务校正太阳实际方向后生成的 `../runtime/material-matrix-gpu.json`。其中驾驶视角、全部光照、Fine直采的受控平面：3–8m直接镜面占最终线性亮度约37.50%，间接镜面约12.14%；8–20m分别约46.12%、10.74%。这已经反对“这套材质根本没生成反射”的判断。随机混合后的总亮度均值变化很小，高通RMS在3–8m/8–20m/20–50m分别降低约12.6%/13.6%/9.1%；与本次CPU统计的额外混合损失同一量级。

这些GPU数据使用真实4K、实际项目光照函数和固定平面，冻结探针，没有赛道建筑/GTAO/雾/阴影；不是完整游戏。它们与本次尺度发现共同支持把问题表述为“反射在空间/角度上的组织与尺度交接不足”，目前不支持只把灯光强度不足认作主因。完整场景的光照、探针和显示链仍需独立核对。

近期最有价值的三件事是：

1. 在当前驾驶机位显示实际normal、roughness、LOD/导数及随机权重，确认Fine为何趋近平法线、用户看到的重复是否与三角格或源大斑块一致。
2. 用同一照明和物理尺度对比Fine与Fresh，保留未增益/未去色原材；根据目标真实赛道的材料状态决定底材，而不是只按近景颗粒“更强”选择。
3. 给一小段路增加有位置依据的粗糙度/材料状态变化，并保留无宏观层对照；同时评估保留微结构统计的过滤候选。两者解决不同问题，不能以增加污渍掩盖基础反射问题。

当前证据不支持立即翻绿通道、全路加大normal、全面降roughness、关mip、增加SSR或把所有法线长度直接换成Toksvig方差。后续研究可以继续，但应带着这些实际数据提出窄问题，而不是再要求一个没有项目输出的广泛综述。
