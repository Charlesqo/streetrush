# 车辆渲染诊断 · 2026-09-20

目前六车的美术质量不一致，整体尚未达到高质量写实赛车游戏的标准。MX-5 的塑料感最明显，来自资产表现、材质覆盖、反射环境与阴影伪影的叠加。当前已有 PBR、清漆、HDR 环境光、太阳阴影和 GTAO；增加效果名称并不能替代画面验收。

本次检查当前本地游戏、六辆原始 GLB、加载后材质规则、灯光与后处理，并进行实机分项对照。没有修改生产代码或车辆资产。

## MX-5：已确认的具体问题

### 1. 车漆校准粗糙，清漆已经存在

`public/cars/mazda-miata-mx5-na.glb` 中的 `Material.002` 使用线性基色 `[1,0,0,1]`，没有车漆颜色、粗糙度、法线或 AO 贴图。原件已经包含 `KHR_materials_clearcoat`，清漆强度 1，清漆粗糙度约 0.01387。

`src/car-materials.js:41` 开始将车漆统一覆盖为粗糙度 0.30、MX-5 金属度 0.12、清漆强度 1、清漆粗糙度 0.13。这相当于把原件很锐利的清漆反射改宽；原始值本身也没有经过实车校准，直接恢复原值不能当作正确答案。

实机中前机盖表现为大块红色，保险杠和翼子板主要靠宽而模糊的亮带塑形。太阳单独照明时大面积红色仍很单一；仅环境光时反射亮带仍在，但清晰场景结构不足。因此需要同时校准底色、表面响应及反射输入。

缺少贴图不是塑料感的充分条件：光洁素色漆可以主要由常量参数构成。真正需要的是经过参考验证的响应，以及在正确尺度上有效的表面变化。车身基底是金属也不意味着表面应使用裸金属着色；是否加入金属颗粒取决于具体漆种。

### 2. 灯具资产本身的信息不足

唯一的一张嵌入图像是 1024×1024 PNG，已原样提取为 `mx5-source-only-texture.png`。图中尾灯和前部灯片主要是模糊色块与预画渐变；实机尾灯也表现为暗红底上的模糊圆形。单纯增加清漆或贴图尺寸不能生成缺失的灯罩纹理、反射碗和内部光学深度。

这是资产重做或精修项。应按实际车型参考补足需要在追车和近景中读到的结构；也可以使用合理烘焙和材质分层表达，不要求所有内部结构都建成高模。

### 3. 玻璃被统一规则改成近似的灰蓝覆盖层

`src/car-materials.js:47` 开始为玻璃统一设置粗糙度 0.09、清漆 0.65、`transmission=0`，没有颜色贴图的玻璃统一改为 `0x435660`，并使用 FrontSide。MX-5 三种玻璃的原有透明度约 0.847、0.823、0.476 被保留。

实机前挡风玻璃明显偏灰蓝，舱内也缺少清晰的层次。当前规则混合了玻璃、灯罩等不同用途，不能代替逐部件的透光、反射、颜色和可见性校准。透明混合本身可以用于实时游戏；这里的问题不是简单地要求开启昂贵的全场景 transmission，而是颜色、透明度、反射和内饰受光的组合未达到目标。

### 4. 反射存在，但位置和精度受限

`src/rendering.js:76` 的环境采样点固定在 `(-55,2.5,12)`，而当前赛道起点在 `(-320,0,0)`，平面距离约 265 米。正常入口没有随车位置更新环境捕获。

`src/rendering.js:156` 的捕获使用 256 分辨率、0.025 弧度预模糊，捕获时关闭太阳阴影，并隐藏整辆车。材质随后继续对环境图进行粗糙度滤波。

因此当前环境图能提供天空与大体场地明暗，却不能正确提供车旁护栏、附近建筑、车体自身及舱内的局部反射和遮挡。车移动或转弯时，环境采样的方向会变化，但采样地点不跟随车辆。提高反射强度只会放大同一套信息，不能修正地点和缺失遮挡。

这些是实现限制；它们对各部件的影响比例尚需单变量反射对照确认。可以先检验更合适的局部采样点、分区探针、预模糊量与更新策略，再决定是否需要更重的反射技术。

### 5. 后盖斜纹确认为太阳阴影伪影

比较 `mx5-rear-2x.png` 与 `mx5-rear-no-sun-shadow-2x.png`：固定车辆、相机和材质，仅切换太阳阴影，后盖大范围斜条纹随之消失。可以确认它来自太阳阴影系统，而不是车漆纹理。部分缝线或边缘仍存在，不能把所有边缘问题一并归为阴影。

当前主阴影图是 2048×2048，正交覆盖宽度 112 米，名义采样尺度约 5.47 厘米/texel。这个配置同时照顾道路与车辆，对毫米级车身缝隙明显粗糙。后续应检查近车阴影精度、偏移和法线偏移的组合；不能只把偏移加大到阴影脱离物体，也不能用关闭阴影当修复。

### 6. 模型表面仍需专门验证

原件存在顶点法线，不是没有法线数据。翼子板和保险杠局部高光有不够自然的起伏，但当前环境反射也会产生类似亮斑，尚不能仅凭一张图判定全部是法线错误。需要条纹或长条灯反射检查，区分反射输入、曲面连续性、平滑法线和薄片重叠。不要对整个模型盲目加细分。

## 高质量赛车游戏应达到什么

| 观察项目 | 画面应达到的结果 | 本项目的验收方法 |
|---|---|---|
| 车身曲面 | 长条反射沿机盖、翼子板和车门连续转折，接缝处正确断开 | 固定中性照明，条纹反射环境，前后两侧近景 |
| 车漆 | 有可信的底色、掠射角反射和高光宽度；顺光、背光仍像同一种漆 | 根据具体车型与漆种参考校准，固定曝光做多角度对比 |
| 材料区分 | 玻璃、轮胎、喷漆轮圈、橡胶密封条、金属、灯罩一眼能分开 | 同一光照下检查部件，按材质职责逐项调节 |
| 灯具与座舱 | 灯罩下有内部层次；透过玻璃能读到座椅和仪表的合理明暗 | 前灯、尾灯、挡风玻璃正反面近景 |
| 阴影与接触 | 轮胎落地、轮拱有深度，车身无条纹和漏光 | 车辆静止落稳后对照投影、局部遮蔽和实际地面 |
| 行驶状态 | 反射连续变化，格栅、轮圈、边缘不会跳闪或忽明忽暗 | 正常追车、绕车与行驶录像，按目标设备帧时间验收 |

Polyphony 的公开技术报告描述了根据测量数据拟合车辆材质，以及基于 Principled BRDF 的材质体系。这支持“以实物响应校准材质”的方向，而不是按车型名称随意指定金属度。参考：[CEDEC 2023 车辆材质拟合](https://s3.amazonaws.com/gran-turismo.com/pdi_publications/cedec2023.pdf)，重点 PDF 第 11–25 页附近。

rFactor 2 的官方 Carbody 文档将底漆和清漆的粗糙度、反射参数分开控制，并用区域图区分塑料、碳纤维、贴纸等表面，还单独处理凹处反射遮蔽。这与当前宽泛名称匹配、统一参数覆盖的做法形成具体对照。参考：[IBL Carbody Shader](https://docs.studio-397.com/display/DG/IBL%2BCarbody%2BShader)。

这里没有把其他游戏的截图模式、光追展示或宣传画面当作本项目正常驾驶画面的性能目标。应先明确目标设备与帧时间，再选择达到上述视觉标准的技术。

## 建议的处理顺序

1. 以 MX-5 建立一个完整质量样板：实车参考、当前画面、中性材质检查环境和真实赛道共同验收。
2. 优先处理已证实问题：后盖阴影条纹；玻璃和灯罩的材质职责；纯红底色与车漆响应的校准。每次只改变一个因素，固定曝光与机位。
3. 单独处理环境反射：先验证采样位置和清晰度，再评估局部更新或多探针方案。不以“更亮”作为完成标准。
4. 精修 MX-5 灯具、轮圈、轮胎、密封条和可见内饰。材质验证后再决定哪些几何必须修改。
5. 修复 E30 可见轮组圆盘问题，并把其余五车按各自源数据校准，避免复制同一组参数。
6. 静态画面通过后，用正常分辨率、动态驾驶和目标硬件验证稳定性及成本。
