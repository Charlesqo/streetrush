# 浏览器模拟按键：LP700 平地 200 km/h 制动

这次在真实 Chrome 游戏页面中运行，使用正常 main.js 主循环、输入控制器、物理步调度器、TrackSystem 和 v24-active 车辆物理。没有直接传入人为构造的 throttle/brake，没有设置车速或更改车辆参数。

诊断脚本向游戏 canvas 发送 DOM KeyboardEvent；事件冒泡到游戏正常的键盘监听器，随后由 InputController.update 自己产生踏板值。这是浏览器模拟按键（isTrusted=false），不是操作系统硬件键盘事件。

实际捕获到的事件顺序：

1. W 按下：持续加速。
2. W 松开：上一物理步的纵向速度为 200.0719 km/h。
3. 同一浏览器帧 S 按下：立即刹车，没有额外滑行阶段。
4. 达到停车阈值后 S 松开。

四个事件的 target 都是 game，见 keyboard-events.json。记录中的加速阶段 rawThrottle=1、rawBrake=0，制动阶段 rawThrottle=0、rawBrake=1；全部物理步转向和手刹输入均为零。第一制动步的滤波油门仍为 0.95456、刹车为 0.04544，体现真实控制器的踏板过渡；没有人为清零滤波状态。

## 本次结果

- 未复现打转；2,865 个物理步连续保留，求解报告全部 COMMITTED。
- 加速到目标约 10.083 秒；制动阶段 9.025 秒、198.551 米。
- 制动阶段最大车头变化约 0.08477°，横向偏移约 0.08020 米；相对第一制动步计算。
- 最大制动偏航角速度约 0.000804 rad/s；后轮单轮最低载荷约 1,436.24 N，没有归零。
- 制动阶段最后水平速度约 0.35613 km/h，松 S 后继续记录约 0.75 秒，最终水平速度 0.05429 km/h。
- 没有自动重置、制动中进入倒挡或页面运行异常。

停车条件沿用浏览器诊断器：水平速度低于 0.5 km/h 持续 0.1 秒后松开 S，再观察约 0.75 秒。不是数学上的严格零速。

场景使用生产 TrackSystem 的平直诊断路段，非龙湾赛道本身；车辆正常从主菜单开始一次比赛，经过倒计时和静置后才给油。目标速度在物理步中检测，按键在下一浏览器输入帧切换，所以允许稍微超过 200 km/h。本次最大速度 200.4591 km/h。

这个结果证明此按键工况也没有触发问题，不能推出用户在实际赛道上没有问题。下一步需要比较真实出问题时的输入历史、车身侧滑/偏航和地面接触；目前没有依据把原因直接归给方向盘。

## 文件及复跑

```powershell
node scripts/record-flat-braking-keyboard.mjs
```

脚本启动独立本地 Vite 服务和 Chrome，进入 `?straightline=1&car=lp700&targetkmh=200&coastseconds=0`，点击测试按钮，保存数据后关闭本次浏览器与服务。使用 Playwright；可通过 PLAYWRIGHT_MODULE 和 CHROME_PATH 环境变量指定安装位置。

- recording.json：完整每步输入、车身、四轮接触/载荷/轮速、轮胎几何、制动、辅助和力矩数据。
- telemetry.csv：本次导出的常用通道，2,865 行；原始 JSON 是完整记录。
- keyboard-events.json：浏览器捕获的四个键盘事件。
- summary.json、metadata.json：结果、协议、浏览器版本与记录时的源码哈希。
- finished.png：运行完成后的实际页面截图。

本次开发只扩展诊断入口的目标速度、滑行时间参数并新增浏览器启动脚本；旧入口默认仍为 140 km/h 和滑行 1 秒。没有修改车辆物理模型或调参。记录前后采样源码哈希一致；记录完成后，仅修正启动脚本的页面等待超时参数位置，未改变测试协议或游戏代码。
