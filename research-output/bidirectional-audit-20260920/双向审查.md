# StreetRush 双向审查 · 2026-09-20

结论：用户描述的两类问题都存在。最值得先处理的缺口，是**局部遮挡与间接照明的空间关系，以及资产共同遵守的受光约定**；最明确的“名字变成事实”，是**按材质名称猜用途，再由猜出的类别决定整套参数**。已有功能并非全是假实现；问题集中在近似的边界、跨系统职责和验收没有闭合。

本次独立审查，不使用子代理，不修改生产代码。先从完整画面的要求列出必要关系，再独立盘点实际数据、材质、shader 和 pass，最后对账。此前单车实验仅作历史背景，没有采用其中候选参数。

## 两条路线的对账

上层依据是项目已有的“车与环境统一自然受光、背光保留细节、接地与遮挡可信”，以及正常驾驶时道路可读、画面稳定的目标。没有把某个商业引擎的功能清单当作需求。

| 从目标往下问 | 从实际实现往上查到的事实 | 裁决 |
|---|---|---|
| 相同材质在敞开处和遮蔽处应有合理差别 | 太阳有投影；天空/场地间接光来自一个全局 PMREM 和一个半球灯，没有按位置查询的间接光可见性 | 直接光存在，局部间接光关系缺失 |
| 车漆、织物、橡胶、透明窗、黑色饰板有可解释的不同响应 | 用名称正则生成 `paint/glass/plastic/metal/...`，然后统一覆写参数 | 缺少明确的资产材质合同 |
| 車与地面的关系应随间隙、坡度、地面变化 | 太阳投影、屏幕 AO、固定车底透明贴片共同提供暗部 | 有投影；贴片不能证明存在接触求解 |
| 车、路面、树、烟在同一个光照条件下成立 | 树是 unlit 图片加亮度补偿；烟另用固定环境颜色；其余主要是 Standard/Physical | 受光模型存在不同口径，尚无清晰的近似边界 |
| 遮蔽只影响它所描述的光传输 | GTAO 在完整场景颜色之后相乘 | 遮蔽与全部画面明暗耦合 |
| 运动时远处边线、栅栏、高光稳定 | 4× MSAA；栅栏有覆盖过滤；没有时间历史，也没有全体细节统一的过滤/LOD策略 | 不能用静态截图或“有抗锯齿”证明运动稳定 |
| 降级应依据真实运行速度 | FPS 分母复用了最大 50ms 的截断帧间隔 | 已复现计量错误 |

## 1. 材质名字正在充当未经确认的用途定义

位置：[分类规则](E:/Projects/streetrush/streetrush/src/car-materials.js:10)、[参数覆写](E:/Projects/streetrush/streetrush/src/car-materials.js:38)。

盘点了六辆车的真实 GLB，共 234 个源材质：108 个被名称规则分类并调整，126 个落入 `authored`。这两个数字表示规则覆盖，**不代表前者正确或后者错误**。

实机与源数据对照确认：

- GT3 RS 的 `TwiXeR_992_blackGlass.001` 是不透明材质，源线性底色 `[0.01379, 0.01379, 0.01379]`。因为名字含 `glass`，被改成 `[0.05613, 0.09306, 0.11697]`，加 clearcoat 0.65；它仍然不透明。透明车窗与不透明黑色表面共用了修改规则。
- LP700 的 `Vitre_noir` 也不透明，同样得到上述蓝灰底色，roughness 从约 0.997 变成 0.09。
- `fabric`、`leather`、`seat` 都被并入 `plastic`。GT3 RS 的一块织物 roughness 从约 0.977 变成 0.65。
- `carbon` 也归入 `plastic`；只有源材质已经是 Physical 时，代码才给它 clearcoat。实机 GT3 RS 碳纤维车顶仍是 Standard，因此该分支根本不会赋予清漆层。相同语义是否有这个层，取决于导出器此前用了哪种材质类。

源材质的每个数字不一定都正确；问题是代码没有记录“这块几何是什么、哪些通道可信、为什么覆写、透明和投影应如何处理”。继续通过全局曝光、环境强度或高光去改善它，会同时改变分类正确的资产。

**整顿优先级：高。** 应先形成逐资产的明确用途与参数保留规则；名字可辅助定位，不能作为最后的材质裁决。未知项应可见，不能默默等同于已验证的 authored。

证据：[完整源材质清单](source-materials.json)、[六车运行时清单](runtime-car-materials.json)、[确定性复现](contract-checks.json)。

## 2. `environment` 确实有照明，但没有局部空间可见性

位置：[环境捕获](E:/Projects/streetrush/streetrush/src/rendering.js:156)、[全局环境与半球灯](E:/Projects/streetrush/streetrush/src/rendering.js:39)、[正常启动接线](E:/Projects/streetrush/streetrush/src/main.js:1408)。

实际链路是：在 `(-55, 2.5, 12)` 捕获一次场地，生成 PMREM，赋给全局 `scene.environment`；半球灯另作填充。正常起点车辆在 `(-320, 0.685, 0)`，水平上距探针约 265 米。捕获时关闭太阳阴影，并且保留场景此前已有的环境照明。因此它是经过照明的单点场景图，不能当作各处局部光传输的解。

同一 PMREM 同时参与材质的环境漫反射和环境镜面反射。旋转/移动车辆会改变采样方向，但不会切换到车辆所在位置的环境，也没有建筑遮挡天空、局部区域过渡或反射视差校正。正常场景盘点中没有 LightProbe，也没有材质 lightMap；历史局部探针实验未接入生产。

**缺的不是“漫反射公式”，也不能笼统说没有间接光。缺的是位置相关的照明与遮挡关系。** GTAO 可以补可见表面附近的凹处，半球灯可以抬暗部，但二者都不能告诉场景“这块表面有多少天空被屋顶挡住”。单纯增加 AO 或降低全部补光，会把局部缺口变成全局明暗调整。

**整顿优先级：高。** 先定义敞开路面、车底/车内、建筑檐下等代表区域应该满足的关系，再决定采用何种受预算约束的近似。本次没有据此宣布必须上完整 GI、光追或某种新引擎。

## 3. “有阴影/AO”掩盖了三种不同职责

位置：[车底贴片](E:/Projects/streetrush/streetrush/src/assets.js:250)、[贴片材质](E:/Projects/streetrush/streetrush/src/car-materials.js:88)、[后处理顺序](E:/Projects/streetrush/streetrush/src/render-pipeline.js:79)。

太阳投影真实存在。车底另有一个固定尺寸、固定透明度 0.36 的圆形暗贴片，作为车辆模型子节点；它没有地面采样、投射、离地衰减或地面法线输入。在审查实例中只把可视根节点抬高 2 米，贴片世界高度从 0.05 变成 2.05 米，透明度保持不变。这证明的是贴片的变换行为，不是一次跳车物理测试。[原始记录](contact-invariance.json)

GTAO 使用主深度重建几何关系，当前半分辨率、16 samples、blendIntensity 0.75。但其结果乘在已经绘制好的整张场景颜色上，直射光、高光、自发光与已经合成的透明物体都可能受影响。已安装 Three.js 的 [GTAOPass 合成](E:/Projects/streetrush/streetrush/node_modules/three/examples/jsm/postprocessing/GTAOPass.js:571)明确是先拷贝场景颜色，再乘 AO。相对地，材质自身的 [aoMap 实现](E:/Projects/streetrush/streetrush/node_modules/three/src/renderers/shaders/ShaderChunk/aomap_fragment.glsl.js:7)作用于间接光分量。

这不是“GTAO 没实现”，而是当前后处理没有区分光照分量。把它当作接地、局部天光遮挡、自阴影和对比度的统一旋钮，会让一种调整同时改掉多种现象。

**整顿优先级：高。** 明确太阳投影、间接光遮蔽和保底贴片各自的职责。保留近似可以，但需写出适用条件和失效条件，不能用叠加暗色来宣称空间关系已经解决。

## 4. `receiveShadow = true` 不代表对象真的接受投影

位置：[批量设置标志](E:/Projects/streetrush/streetrush/src/rendering.js:147)、[树的材质](E:/Projects/streetrush/streetrush/src/track-detail-materials.js:40)。

运行时两批树共 348 个实例，都显示 `receiveShadow: true`，但实际材质是 `MeshBasicMaterial`，其 shader 没有太阳受光和阴影采样。亮度来自图片、`[2.8, 2.85, 2.65]` 乘色，以及 `pow(..., .82)` 和固定颜色加项；树也不投影。于是对象标志看似“加入了统一阴影”，画面上却没有对应机制。

烟的 shader 确实读取太阳方向、强度和阴影，但环境颜色固定为 `[.32, .38, .46]`，没有同步 PMREM 或半球灯。不能把“烟受光”自动推广为烟与其他表面共享了完整照明。[烟的环境输入](E:/Projects/streetrush/streetrush/src/tire-effects.js:131)

远景 unlit 树、艺术化烟本身可以是合理预算选择。缺失的是明确的近景/远景适用范围和共同的画面校准条件；当前这些补偿藏在局部 shader 中，全局光照调整无法可靠地让全部资产一起变化。

## 5. 画面稳定与成本控制尚未形成可验收的完整约定

当前真实配置是 4× MSAA，不是旧报告中的桌面 2×/触摸 0×。输出链没有时间历史；栅栏有单独的像素覆盖过滤，但道路细线主要仍是独立几何，场地实例批次跨很大空间，尚无一致的空间分块/距离 LOD。

这不意味着一定要加 TAA。缺的是覆盖正常追车运动的稳定性标准，以及哪些高频细节在远处如何退化的规则。单张漂亮图片、增加 MSAA 或降低主分辨率，各自都只能回答其中一部分。本次静态截图**不能量化当前运动闪烁程度**。

另外，画质控制器主要降低 AO 分辨率，再降低全屏分辨率；没有先区分 CPU 与 GPU 瓶颈。因此“自适应画质”不能自动等同于“已经解决低性能设备问题”。这点是实现能力边界，尚未在本轮进行设备性能矩阵验证。

## 6. 其他方面：FPS 的含义确实发生了混用

位置：[FPS 分母](E:/Projects/streetrush/streetrush/src/main.js:1195)、[帧间隔来源](E:/Projects/streetrush/streetrush/src/main.js:1225)。

`frameDt` 在进入性能面板之前被限制为最多 0.05 秒。这种截断有自己的用途，但它不再是完整墙钟时间。面板却使用 `renderedFrames / 累计frameDt` 作为 FPS。

用实际 `updatePerformance` 函数的代码、固定输入帧间隔复现：60→60、30→30、20→20、**10→20、5→20**。降级采样窗口也会在低帧率下按实际时间拖长。这里应将真实墙钟计量与用于模拟/动画的时间步分开，不能因为变量仍叫 dt 就认为两者等价。[复现脚本](contract-checks.mjs)

还查到追车相机只有位置/目标缓动、FOV 和震动，没有遮挡检测或相机避障；这是明确缺项，但本轮未复现具体赛道位置的穿墙画面，列为待验证，不提升为已验证视觉缺陷。车辆动力学不在本次裁决范围。

## 已排除的误判

- Standard/Physical 的直接漫反射及间接光计算都存在；不是缺一条 Lambert 公式。
- 正常路径是线性半浮点场景目标，最后统一 OutputPass 做 ACES 与 sRGB 输出；未发现“整条链没有色彩管理”的证据。
- 环境反射确实存在，而且是静态复用；不是每帧捕获六面。
- 太阳阴影与 GTAO 都有实际执行；上述问题在职责、覆盖域和组合方式。
- 路面 DFG LUT 试验、历史局部 diffuse probe 文件的存在，不代表已接入生产。不能把研究目录当作当前能力清单。
- 本轮实机是正常入口的场景、素材与光照配置，之后仅在审查实例中冻结相机/画面或切换诊断开关。没有采用单车修补候选。
