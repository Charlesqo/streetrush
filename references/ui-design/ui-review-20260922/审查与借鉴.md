# Street Rush：UI 审查与外部 skill 借鉴

日期：2026-09-22。范围：当前本地游戏的玩家界面、文案和信息层级。此文件是研究记录，不是可执行 skill，也不是游戏接入方案。

## 结论

当前最需要修正的是信息取舍和表达方式。作者的项目介绍、系统内部状态和玩家的比赛信息混在同一层；最醒目的文字又经常不帮助玩家操作。单纯换配色、字体或加动效，会保留这些问题。

建议先围绕三个玩家任务重新安排界面：选车并开始、驾驶并判断成绩、查看结果并重开。整体方向以清楚、克制的赛道计时界面为宜，让车、赛道和成绩成为主角。

## 检查范围与证据边界

- 实际打开本地开发页面，查看了选车菜单、发车倒计时、静止状态的比赛 HUD 和暂停菜单。主菜单及首次 HUD 截图为 1280×720；暂停时应用面板宽度发生变化。
- 本次浏览器页面实际显示了触摸控件，因此这不是纯键鼠桌面布局的完整验证，也不能代替真机手机测试。
- 另行阅读了生产 `index.html`、`src/main.js`、`src/style.css`、相关车辆显示配置和目标显示代码。没有完整跑完三圈；结算、每次过检查点和无效圈反馈的结论来自源码。
- 没有修改生产代码，没有安装、调用或执行任何外部 skill、脚本、hook。只为查看现状启动了项目已有的本地 Vite 服务，没有运行构建或测试套件。
- `index.html` 中“数据已记录，下一圈继续压榨极限。”是初始占位，运行时结算函数会覆盖它，不能把这句当成已实测的最终结算文案。

完整动力诊断面板和性能面板默认隐藏，不应描述成全部默认展开。底部接地、路面与辅助状态在桌面规则下存在，当前触摸布局截图未显示；应分别处理。

暂停菜单是可以保留的基础：继续比赛、重新开始、退出到主菜单三个动作清楚，主操作突出。无需为了统一“重做”而把这一部分也加复杂。

## 找到的公开 skills：借什么，不照搬什么

以下均按作者仓库阅读；链接指向查询当日的 main 分支，后续内容可能变化。下面是研究判断，不代表已启用它们。

| 来源 | 借鉴价值 | 在本游戏中的取舍 |
|---|---|---|
| [OpenAI · game-ui-frontend](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/game-ui-frontend/SKILL.md) | 专门面向浏览器游戏，强调保护可玩视野、清楚的信息层级、长说明收起、事件提示短暂出现。 | 最适合作为 HUD 布局参考。其通用 3D 信息组数量和覆盖比例只是起点，不能机械删掉赛车计时或触摸控制。 |
| [Impeccable · clarify](https://github.com/pbakaus/impeccable/blob/main/skill/reference/clarify.md) | 优先表达当前事实和下一步操作；统一术语；避免重复标题、解释和帮助文本。 | 最适合处理当前“怪文字、自言自语”。保留真正帮助判断的赛车术语，不把所有缩写都扩写成长句。 |
| [Impeccable · distill](https://github.com/pbakaus/impeccable/blob/main/skill/reference/distill.md) | 按当前任务删减重复信息和装饰，减少同时展开的次要内容，拉开主次。 | 借用信息取舍方法；不要照搬网页纵向排版、大留白或移除侧栏的具体布局。赛车 HUD 要围绕驾驶视野安排。 |
| [UI UX Pro Max · quick-reference](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/src/ui-ux-pro-max/templates/base/quick-reference.md) | 可用于检查对比、交互状态、图标一致性、数字稳定性和非纯颜色反馈。 | 作为细节检查表，优先级低于前两类。它的 Web/App 风格库不能直接决定赛车游戏的艺术方向。 |
| [Anthropic · frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) | 可参考视觉方向一致性、文字服务操作、从用户角度命名等原则。 | 作为补充，不把网页大标题和排版实验搬进驾驶 HUD。 |

优先组合是：game-ui-frontend 的游戏视野约束，加 Impeccable 的 clarify / distill 文案与删减原则。没有必要先装一套“大而全”的 skill。

Impeccable 当前完整入口涉及 launcher / 引擎与 hooks；UI UX Pro Max 完整流程会运行 Python 查询并可持久化设计文件。这些流程均未执行，也未作为本次工作指令。这里只摘取思路，未进行完整脚本安全审计。

## 针对当前文案的对照建议

这些是本次提出的改写示例，尚未写入游戏。

| 当前内容 | 建议 |
|---|---|
| 今天，跑哪一台？ | 选择车辆；也可以直接以当前车名为主标题 |
| 晴空试车计划 / 01 | 3 圈计时赛 |
| 六台真车模型……控制轮胎负载，跑出三圈稳定节奏。 | 删除；在模式位置保留“龙湾国际赛道 · 3 圈” |
| READY / PB ACTIVE / TARGET SET | 正常状态不额外播报；显示真正的记录或差值即可 |
| 完成 3 个检查点后计算 | 尚无预测时显示“—”，或暂时隐藏预测项 |
| 漂亮收车。 | 比赛完成 |
| 还有下一圈。／本次成绩未认证 | 含无效圈；结果详情解释对总成绩和有效单圈的影响 |
| 预编译光照与材质… | 正在准备赛道… |

不需要把所有个性都清除。游戏名、车辆造型、排版节奏和少量关键事件反馈可以表达气质；普通状态和操作说明应当可靠、简短。

## 建议的后续顺序

1. 先定一张内容表：每个信息属于常驻、事件短显、详情，还是调试。涉及当前三圈成绩和有效性的必要信息不能因“极简”丢失。
2. 只做主菜单、比赛 HUD、结算三个独立预览，统一背景和示例数据；先比较任务是否清楚、文字是否减少、关键读数是否更容易看见。
3. 再决定字体、配色和装饰。优先延续已有赛道与车辆画面，让整体更接近计时赛车游戏；无需先扩展成多套完全不同的视觉主题。
4. 预览确定后再考虑接入。本次没有制作新预览或接入游戏。
