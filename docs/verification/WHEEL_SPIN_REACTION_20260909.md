# 制动车身力矩修复：2026-09-09

## 交付范围

用户基于第三段正常游戏记录，要求评估并处理高速制动失控。当前仅修复 `src/vehicle-v24/runtime.js` 中接地点轮胎力与附加车轮自转反作用的重复记账路径，并保留离地车轮的驱动/制动反作用。

Rapier 已在接地点施加完整轮胎力和力矩；附加项现在采用本步车轮净力矩 `Tdrive + Tbrake + Tcontact`，投影到当前车轮轴向的反方向。该处理适用于加速、滑行和制动，不按踏板状态切换公式。AIRBORNE 时接触力矩为零，独立车轮自转和制动反作用仍保留。

本次未修改发动机参数、刹车能力、ABS/TCS/ESC、轮胎定律、方向盘灵敏度、载荷求解器或车身状态；没有用角速度阻尼补丁、直接轮速/车速赋值或自动重置来抑制旋转。起步朝向在前一轮独立修正。

## 权威边界

遵循 v2.0 baseline 的独立 wheel spin DOF、离地保留传动连接、world/vehicle split 与外力各计一次原则。本修复明确是当前 Rapier 接地点外力与独立车轮转动模型之间的宿主记账修正。

v2.4 `unified_vehicle_fixture.py:1526` 的 reduced quasi-static host 本身另加制动反作用，其系统边界不同；本次不声称与该 fixture 的俯仰/载荷结果严格等价，也不修改 reference/golden 来制造通过。所有 backend `UNDECIDED` 项保持原状。完整 coupled solver、轴方向输运/陀螺项、发动机和传动系整体角动量、现有轮速 clamp 等仍不在本次闭合证明范围内。

### 撞墙回归的调查与测试修正

初版修复导致既有 playability 的 `forward drive did not resume after reverse escape` 断言失败。完整记录显示前进挡已接入，车速已恢复至 2.78 m/s；随后固定时序的逃离轨迹再次碰到墙，最终速度接近零。旧版本倒车后的制动停止位置约 z=−0.19，新版本约 z=+0.30，导致原先紧贴障碍的脚本路线结果变化。

测试原来以车身中心 z<2 作为倒车腾空条件，墙在 z=4.5；这只保证脱离碰撞面，不保证有停车和转弯空间。现在退回起始位置之外（z<0）再开始前进转弯；仍保留前进速度、事务提交、无自动重置检查，并新增最终无墙体接触断言。该测试在旧、新两套 runtime 下均通过。没有为此修改实际车辆换挡、刹车或转向代码。
