# Street Rush 延期整改总账

更新日期：2026-08-21

这份文档是后续整改的单一入口。当前阶段只记录事实、保留证据和确定处理顺序，不在本次工作中修改游戏、音频、车型资产或物理参数。

## 1. 当前决定与真实代码状态

### 当前产品决定

- 暂时只认可并优先使用两辆车：`mx5`（MAZDA MX-5 NA）和 `gt3rs`（PORSCHE GT3 RS）。
- `lp700` 虽然已有运行时车轮绑定，但尚未完成近距离人工视觉确认，暂列“隔离待确认”，不计入上述两辆。
- `m3e30`、`amggt3`、`m5g90` 当前视觉资产不应被视为可交付车型。
- 当前试听过的六套量产音频全部按“人工否决”处理；现有音频代码可以保留，音频素材不能因测试通过而自动恢复为可用。
- 物理代码保留为可用的 simcade 基础，不做大迁移；旧 C++ 研究核心只作为校准与算法参考。

### 代码现状（避免误读）

- 游戏目前仍展示六辆车；本次没有隐藏或禁用另外四辆。
- 游戏目前仍会加载现有音频银行/程序化回退；本次没有关闭声音。
- 本次没有替换模型、重新导出 GLB、修改车辆物理、改变赛道或增加玩法。
- 因此，“只用两辆”和“现有音频已否决”是后续实施策略，不是已经完成的运行时限制。

### 模型问题的共同根因

- 旧的 glTF-Transform 4.4.1 优化流程把层级、材质所有权和动态部件合并得过度。
- 当前仓库没有一条可复现的 AMG/M5 资产优化流水线，无法证明以后重导会得到同样且正确的结果。
- “加载器测试通过”只证明节点绑定和生命周期不崩溃，不代表外观正确。
- 生成几何轮只能当诊断工具，不能作为最终车型资产。

### 模型以后应怎样做

1. 以原始 GLB 为唯一事实源，先保存文件哈希和节点/材质审计结果。
2. 建立可复现的资产构建脚本；对轮胎、轮圈、刹车盘、卡钳、灯光等动态分支禁止 join/palette merge。
3. 在资产构建阶段保留车轮轴心和所有权，尽量避免运行时切几何。
4. 清单必须绑定源文件哈希，源模型变化时显式失效，禁止静默套用旧清单。
5. 接入 `omega`、`steerAngle`、`compression` 后，必须由真人近距离检查正转/倒转、左右打满、刹车盘和卡钳、悬挂压缩、重新选车与重启。
6. 一个车型通过后再处理下一个，不同时重做多辆。

## 4. 音频总账

### 当前结论

- 已试听的现有声音整体呈持续电钻/窄带合成音，全部按人工否决处理。
- 当前选择银行覆盖 6 辆车、3 个 RPM 锚点、油门开/关，共 36 个 WAV；它们是格式完整的循环素材，不等于听感合格。
- 六套素材都只有 `exhaust_mix`，没有独立进气、机械、涡轮、气门、传动、回火或环境声部。
- MX-5 的周期性/电钻感最明显；AMG 的 on/off 近乎相同（相似度约 99.98%，响度差约 0.06 dB）；M5 的负载和响度行为也不可信。
- `E:\Codex\autonomous_runs\multi_car_audio` 中约 35 组、约 210 个 WAV 基本都来自同一 Engine Simulator 0.1.11a 生成体系。它们有不同脚本和字节内容，但不是一批隐藏的真实车辆录音。
- 资料中写的“public-source”主要表示公开 `.mr` 脚本，不表示真实汽车录音，也不自动解决授权和听感问题。

### 可以保留的音频工程

- 共享 AudioContext 和声音银行加载协调器。
- 缓存、取消加载、防止过期结果发布、暂停/恢复、车型切换和重复进入比赛的生命周期处理。
- 程序化回退机制可以保留为容错代码，但其声音本身没有获得人工认可。
- 已有试听审计文档：`docs/AUDIO_LISTENING_REVIEW.md`。

### 应否决的内容

- 当前六套被选中的 WAV 银行及同体系候选素材，不应靠 EQ、交叉淡化或再加一层失真来“修好”。
- 不应因为波形无爆音、循环无断点、自动测试通过就标记为可交付。
- 不继续一次生成六辆车；先把一辆的声音做对。

### 音频以后应怎样做

1. 保留当前坏样本和指标作为失败证据，运行时再实施隔离/禁用；不要现在删除原始资料。
2. 二选一：采用来源与商业权利清楚的真实车辆录音，或只为一辆车做新的程序化原型。
3. 新程序化原型至少应分开表现排气脉冲、进气宽带、机械噪声、负载瞬态，并加入轻微 RPM 抖动，避免静态谐波长期锁相。
4. 每次只交付三段短试听：怠速到中转、全油门扫转、收油/换挡。
5. 必须由人先听；只有一辆通过后，才能扩展到其他车型。

## 5. 物理总账

### 当前可保留的基础

- Rapier 刚体与四轮射线车轮。
- 悬挂、纵横向滑移、摩擦圆、驱动、制动、手刹、ABS/TCS、稳定辅助、气动阻力和路面分类。
- 车辆重置/恢复、固定步长、确定性检查以及碰撞快速测试。
- 现有六车 smoke、加速/制动/圆周、MX-5 handling、输入边界、重置、内部恢复和确定性测试均曾通过。
- Rust/WASM 当前负责固定步长调度、比赛进度/计时和回放相关共享逻辑；它并不负责车辆动力学，不需要为“看起来高级”而扩大职责。

### 已知物理风险

- 当前轮胎力主要是基于 `tanh` 的 simcade 标量模型，不是高保真轮胎模型。
- 低抓地稳定辅助曾能直接制造超出路面预算的横向 G；2026-08-21 已让目标横摆和修正力矩受承载车轮的抓地限制，并加入砂石/草地回归。MX-5 场景从砂石约 0.65g、草地约 0.61g 降至约 0.42g/0.36g，沥青仍约 0.70g。
- 量产标定测试主要在平坦无限沥青上完成，不能覆盖真实赛道边界、路肩和复合路面。
- MX-5 回转遥测曾出现约 1.32g 峰值，而轮胎参数 `mu=0.98`；现有测试容差较宽，不能据此宣称标定准确。
- 赛道为平面，悬挂基于通用 world-up 射线；没有真实路面高差或路肩几何反馈。

### 旧物理研究中真正有用的内容

- `E:\Codex\vehicle-physics-core`：可移植 C++20 研究核心，包含 TMeasy、Fiala 参考、SharedRide/SharedWheel 模型与约 20 个 C++ 测试文件。
- `E:\Codex\research_continuation_20260810`：物理复现、场景和审计记录。
- `E:\Codex\autonomous_runs\multi_car_physics_data`：六车参数证据包。
- 可复用价值主要是 TMeasy/车辆测试作为离线 oracle，以及制动、滑行、转向场景和有来源的质量、轴距、传动比、CdA 数据。
- 旧报告明确给出 `productionMappingReady=false`；这些代码没有 Street Rush 量产适配层，不能直接说“已经接入”。

### 物理以后应怎样做

1. 继续只修有实机影响且可复现的问题；低抓地稳定辅助已完成，下一项必须来自两辆主车的持续驾驶证据。
2. 建立最小失败测试，再改当前 JS/Rapier 实现；不要先迁移整个 C++ 核心。
3. 用 TMeasy/Fiala 和旧离线场景做对照 oracle，不把研究核心直接塞进 WASM。
4. 每次参数修改都同时跑沥青、砂石、草地以及碰撞/重置回归，再由真人判断手感。
5. 不迁移尚不完整的 10/14 状态 SharedRide/SharedWheel 系统；其单边接触、水平动力学、动力总成和目标数据仍有缺口。

### 外部物理研究实际完成了什么

- `vehicle-physics-core` 不是空壳：现有已编译测试包含 16 个通过的套件，覆盖 TMeasy、Fiala、基础 Vehicle、quarter-car、four-corner ride、SharedRide、SharedWheel、质量矩阵、轮端耦合与多种 Miata 敏感性夹具。
- 基础 `Vehicle` 是独立的 C++ 六自由度刚体与四个无质量轮站，包含有状态 TMeasy 轮胎、低速混合、松弛长度、载荷插值、联合滑移、车轮转动惯量、空气/滚阻以及能量/功率遥测。
- Fiala 实现是无状态稳态轮胎 oracle，主要用于检查曲线、符号、联合滑移和回正力矩，不是第二套已经标定好的量产轮胎。
- quarter-car、four-corner、SharedRide 和 SharedWheel 做了垂向质量、悬挂、轮胎垂向刚度、接触丢失/重入、能量守恒及 10/14 速度状态研究；其数值测试很完整，但目标车型参数和水平轮胎状态仍不完整。
- `multi_car_physics_data` 主要是六车资料证据库和使用边界，不是六辆已经调好的物理预设。当前仓库已保存其筛选投影，共 21 个可进入模型接口的来源字段：AMG 0、GT3 RS 6、LP700 3、M3 E30 2、M5 G90 5、MX-5 5。
- `research_continuation_20260810` 完成了大量 owner、符号、时间积分、微步预算、trace 和 Street Rush 映射复现；最终映射结论仍是 `productionMappingReady=false`，没有量产 adapter。

### 明确不能直接接入

- 不把 `vehicle-physics-core::Vehicle` 整体编成 WASM 覆盖 Rapier：两边刚体、接触、状态和时间步 owner 不同，会出现双重物理所有权。
- 不接 SharedRide/SharedWheel 10/14 状态系统：它仍缺完整水平轮胎状态、单边事件闭环、转向轴运动、横向轮惯量、真实非簧载参数和车辆级相关验证。
- 不把 Fiala 当量产轮胎替换 TMeasy：它在这里是稳态对照 oracle，两者的联合力和回正力矩已有明显差异。
- 不直接使用 Miata 推导弹簧数值：前约 27.65 kN/m、后约 16.64 kN/m 是线圈刚度推导，不是轮端刚度；运动比、座角、预载、限位块和非线性仍未知。当前统一 `28.5 kN/m` 也不能因“接近前值”就算验证通过。
- 不宣称 21 个筛选字段等于六车物理完成：它们绝大多数是质量、轴距、前后轮距、轮胎尺寸/压力和 CdA，AMG 甚至没有可直接进入模型的选中字段。

## 6. 玩法与系统的其他问题

### 真人游玩闭环仍缺证据

- 浏览器曾检查：车库选车、开始、倒计时、HUD、相机、计时、暂停冻结/恢复、重启、重置判无效、快速重启、返回车库和多车切换；控制台当时无明显错误。
- 2026-08-21 已取得持续输入证据：MX-5 直线持续油门 11 秒达到约 88 km/h 且圈有效；GT3 RS 达到约 126 km/h、圈有效并通过检查点 1；同时油门/转向可持续生效。实测同时抓到起跑样条接缝令车辆初始朝向偏约 5.7°，该问题已修复，100 米直行中心偏移由约 9.23 m 降至约 0.68 m。
- 浏览器自动化没有真正完成“持续按住键盘或真实手柄并跑完三圈”的人工验收。
- 仍需真人完成：车库选车 → 键盘持续驾驶 → 手柄持续驾驶 → 三圈 → 暂停/恢复 → 重启 → 冲线 → 成绩 → 再来一次。
- 先只验收 MX-5 和 GT3 RS，再决定是否增加车型。

### 已知系统欠账

- 输入：Gamepad Start/Menu 映射和移动触控 HUD 避让已经修复，但仍需常见手柄、键盘和移动横屏实机矩阵。
- 相机：当前是一套通用 ChaseCamera；旧研究里的逐车相机锚点没有接入。
- 碰撞体：每辆车仍主要使用基于轴距/轮距的通用长方体，不是逐模型确认的碰撞外形。
- 赛道：目前一条约 2.13 km、10 检查点的平面闭环赛道；路面和护栏可用于玩法，但没有真实高差/路肩。当前不需要增加第二条赛道。
- 灯光：模型里多为候选材质/自发光材质，没有可靠的内嵌 Light 节点；车灯、刹车灯和尾灯状态尚未形成量产接入。
- 性能：LP700 运行时切分会增加约 6.65 MB 几何和约 50 ms 的 Node 侧测量开销；AMG 候选约 2.64 MB/89 ms。以后优先在资产构建阶段保留动态部件。
- 授权：车型、模型和音频的公开/商业授权阻塞已有记录。当前不发布、不部署；整改前也不能因为技术可运行而忽略授权。

## 7. 后续实施顺序

## 8. 每一类工作的验收门槛

### 模型

- 近景静止外观无占位轮、压扁、叠层、错材质和明显穿模。
- 正转/倒转方向正确，前轮转向轴正确，悬挂位移不脱离轮拱。
- 刹车盘随轮转，卡钳不跟转；车型切换、重启和返回车库无重复绑定/内存异常。
- 资产构建可复现，清单与源哈希匹配。

### 音频

- 三段指定试听由人明确通过，不能只依赖频谱、相似度或无爆音测试。
- 油门开/关和转速变化可辨，连续加速不呈固定电钻音。
- 暂停、切车、重启、回车库时没有重复播放、泄漏或旧银行串音。
- 录音/生成素材的来源和使用权有可核查记录。

### 物理与玩法

- 键盘与手柄均可连续驾驶三圈并得到成绩。
- 暂停真正冻结计时和车辆，恢复无输入突跳；重启、重置和再次比赛一致。
- 护栏碰撞无穿透、爆速或数值发散；草地/砂石抓地下降符合直觉。
- Rust/WASM 构建、相关单元测试和浏览器回归通过，但自动测试不能替代真人手感。
