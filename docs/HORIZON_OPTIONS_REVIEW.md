# 远景方案评估 — 2026-09-09

## 结论与状态

建议保留现有 HDR 天空，新增独立的三维丘陵/远山、分区树林和少量建筑地标。改善空旷感的工程量中等偏低；自然构图需要多视角迭代。完整可探索城市或扫描地形的成本明显更高。

本轮完成代码检查、两个子代理并行只读评估，以及当前本地版本主直道、南段、鸟瞰画面检查。没有实现候选方案，没有进行候选性能测试或美术验收。

## 当前问题

- `src/track-environment.js`：地形范围 1900×1700 米，起伏理论上限约 35 米。能形成草坡，缺少远山层次。
- 树候选范围 x=-680～680、z=-540～270；经距离和分布规则剔除后留下稀疏树丛，未形成四周连续但有开口的林带。
- 建筑集中于维修区，其余方位缺少方向识别点。
- `src/rendering.js`：已经有 2K pure-sky HDR 天空。正常入口 HDR 模式雾密度为 0.00038，不能把初始化时的 0.00058 当作当前最终参数。
- `src/main.js`：相机 far=1300；直接在几公里外增加山体会出现裁剪。环境捕获远平面也需要一并核对。
- 当前主直道和南段画面确认：大部分天际线由低草坡与小树组成；鸟瞰可见场地边界与天空直接相接。
- 开发检查页面主动限制 5 FPS，画面中的约 5 FPS 不能作为正常驾驶性能结论。

## 路线比较

| 路线 | 成本 | 优点 | 局限 / 结论 |
|---|---|---|---|
| 调雾、曝光、地色 | 低 | 可改善融合 | 不产生轮廓，仅作辅助 |
| 换带地景 HDRI / 天空盒 | 低 | 快速填满地平线 | 地景无平移视差，光照与场地难匹配 |
| 手绘、照片或 AI 全景背景 | 低至中 | 最远层细节丰富 | 接缝、光向、透视一致性需处理；只适合最远层 |
| 分层山景卡片 / 树林卡片 | 低至中 | 少量网格便可分层 | 鸟瞰与侧视容易露馅；透明重叠有开销 |
| 抬高现有地面、增加随机树 | 低 | 复用现有生成逻辑 | 容易变成围墙般草坡，缺少有意构图 |
| 程序化三维丘陵 / 山脊 | 中低 | 有视差、遮挡，可快速调形 | 需要设计轮廓，不能只堆重复正弦波；推荐主体 |
| 人工制作地形 GLB | 中高 | 构图和细节控制好 | 制作、减面与材质整理成本较高；适合后续升级 |
| 购买 / 开源模块化场景资产 | 中 | 可补建筑和植被 | 风格、尺寸、授权和贴图预算需逐项核对 |
| 实例化树林 / 城镇轮廓 | 中低 | 中景丰富、能设置地标 | 单用仍平；树卡需控制重叠；推荐辅助 |
| 真实 DEM / 扫描大地形 | 高 | 地貌真实 | 数据处理、LOD、纹理和传输成本高，当前无必要 |
| 完整可探索城市 / 流式开放世界 | 很高 | 可近看、扩展玩法 | 超出解决远景空旷所需范围 |
| 混合分层 | 中 | 在真实视差、构图、性能之间平衡 | 当前首选 |

## 推荐落地方向

延续晴天常设赛车场的风格：近处保留草坡和设施；中景形成几片深浅不同的林带；远处布置两三层高低错落的丘陵与山脊。部分方向留低开口，另一些方向放低矮厂房、看台或通信塔。避免整圈同高山墙，也避免每个方向重复同一批建筑。

第一轮先做独立可开关的 `src/track-horizon.js`，由环境构建末尾接入。采用静态低模山体与现有树贴图，保留已有近场地形。几何必须避让完整赛道包围范围与服务区。

先用三个构图版本比较：A 低丘+林带；B 双层山脊+林带；C 双层山脊+局部建筑。它们共享技术基础，仅调整布局，避免同时维护三套生产系统。预计 B 或 C 最适合，仍需实际画面决定。

实现检查点：

1. 核对所有驾驶位置至远景的距离，再决定适度扩大相机 far 或独立背景绘制；同时检查深度精度和环境反射捕获范围。
2. 远景不增加碰撞、不投实时阴影、不每帧捕获反射。建筑要设置 `userData.sceneryShadowCaster=false`，避免 `prepareScenery()` 重新开启投影。
3. 树林复用实例化材质，扩大树量时避免每棵都对整片地形进行射线检测，可复用高度采样。
4. 尽量保留现有天空、太阳和曝光，先判断轮廓与布局，再微调远处颜色与雾的融合。

预算目标：新增约 6～12 次绘制、1～3 万三角形。这只是设计预算，不是已测结果，也不构成手机帧率承诺。

## 验收

- 固定主直道、连续弯、南段、西段、反向及鸟瞰视角，保持相同光照与相机参数对比。
- 检查不同方向有无层次和识别点，山体是否突然消失，场地边缘是否露底，背景是否像围墙。
- 沿整圈行驶检查视差、接缝、树卡侧视与裁剪；确认没有进入道路视野的突兀遮挡。
- 在正常刷新率下比较同机同视角的帧时间、绘制次数和显存/资源开销；单独测手机后才给出手机性能结论。
