# 天空、车辆清晰度与轮胎效果的小样计划

2026-09-07。根据用户“先想想、计划一下”的要求，本轮只排查代码和源资产，未修改游戏效果。下面是实施顺序和保留标准，不是已完成的效果或性能结论。

## 已知问题与尚待确认项

- 天空：`src/rendering.js` 使用 Three.js r180 `Sky`，固定午后太阳方向，turbidity=2.8、rayleigh=1.8、mieCoefficient=0.003，ACES 曝光为 0.9。没有昼夜或天气系统。已有实机画面的地平线偏灰白；天空亮度、大气参数与整体曝光的平衡是首要检查项。尚未进行新方案实机对比，不能把“观感偏白”直接等同于已测出的像素裁切。
- 清晰度：`src/main.js` 桌面渲染比例上限 1.35，总像素预算约 320 万；动态分辨率可降到 CSS 尺寸的 0.72 倍。它不是显示器原生 DPR 的 72%。低分辨率再放大会软化轮廓；尚未读到用户当时画面的实际 canvas 尺寸，不能确定当时已降至最低档。
- 后处理：当前没有景深、运动模糊或全画面模糊 pass。GTAO 半分辨率计算的是遮蔽，主颜色目标仍按主画面尺寸渲染。需通过一次开关对比排除合成对主观清晰度的影响。
- 保时捷源资产：`public/cars/porsche-gt3-rs.glb` 包含 13 张图像，尺寸为 128×128 至 1024×1024，包含 256×256、512×512、512×1024；车漆材质有不使用颜色贴图的部分。GLTF sampler 为线性放大、三线性 mipmap 缩小，没有发现人为最近邻过滤。车辆加载代码未提高默认各向异性过滤。低分辨率贴图可能影响局部标志或细节，但不能解释整车轮廓发糊。
- 烟雾：`src/effects.js` 使用无贴图的 `PointsMaterial`，不接受太阳光照，粒子透明度固定；寿命衰减乘到 RGB，结果是颜色变黑而非逐渐透明。粒子没有柔软的形状遮罩，生成数量还与 update 次数有关。
- 胎痕：使用半透明 `MeshBasicMaterial` 和分段薄盒，不接受太阳光照或阴影；没有连续轮胎轨迹、边缘纹理和随强度变化的局部透明度。

## 第一阶段：小样

### 1. 保时捷清晰度诊断

先显示 CSS 尺寸、canvas 实际尺寸和渲染比例。同一车、同一机位、同一阳光下，对比当前自适应结果与固定 1.0 / 1.35 比例；只在有辨别价值时加入一次 AO 关闭对照。保留整幅原图与 1:1 细节观察，分别检查轮廓、标志和反射。

若提升分辨率明显改善整车清晰度，优先调整画质降级顺序：先降低 AO 和阴影成本，再降低主画面分辨率，保留必要的性能兜底。若只有斜视贴图模糊，试验有上限的各向异性过滤；若源贴图本身缺细节，单独记录资产限制。不会把反射图分辨率、锐化或整体拉高 DPR 当成所有模糊问题的共同修复。

### 2. 天空：先调程序天空，HDRI 作为备选

保留当前方案作为 A。B 只做一个明确的晴朗午后：顶部蓝色有层次，地平线保留轻微空气感，太阳周边可亮，但大片天空有颜色差异。

首先调整现有 Sky 的大气参数，必要时加入天空辐射亮度的独立乘数，在统一色调映射之前生效。保持太阳方向统一，并在选定预设时重新生成场地 PMREM，使车漆与天空相符。全局曝光用于整场景平衡，不承担单独压暗天空的全部任务。

若这一个程序天空小样仍明显单调或难以取得自然观感，再尝试一张有明确授权的晴天/少云 HDRI，比较天空细节与反射的收益；对齐 HDRI 的太阳朝向、方向光和反射环境。先核对本地已有素材，再决定是否下载。此阶段不实现昼夜系统。

保留标准：顺光和逆光机位都比当前自然；白车保留表面层次，暗车可读，路面不被压黑；未出现两个太阳方向或反射方向冲突。若达不到，保留当前版本并记录限制。

### 3. 独立烟雾小样

在真实赛道光照下提供固定发射点，支持“仅烟雾”、暂停、重置和固定随机种子，无需先成功漂移。使用相同曝光、天空补光和太阳方向，分别看亮处、阴影处及逆光。

第一版采用软边粒子/朝向相机的面片，加入少量形状变化、尺寸增长、每粒子透明度衰减和轻量散射近似。按时间控制发射率，避免不同帧率改变烟量。保持粒子数量上限。

处理与地面、车身相交的硬边时，优先复用已有深度做柔和相交。烟雾应在不透明场景 AO 后、最终色调映射前合成，避免地面 AO 被错误涂到烟上。这里需要小范围透明效果渲染接线，不涉及车辆物理判定。

保留标准：烟雾从产生到消失不变成黑块，无明显方形边缘或地面切线；逆光和阴影下有合理差异，仍能看清驾驶方向。轮胎烟雾不依赖整场景体积光系统。

### 4. 独立胎痕小样

同一段路提供“仅胎痕”，固定生成一条直线、一条弧线和几档强度，包含跨越太阳阴影的片段。试验连续带状几何、柔软且不完全均匀的边缘、与沥青匹配的高粗糙度材质；接收相同太阳阴影。使用微小偏移/多边形偏移避免闪烁，保留实例或几何容量限制。

保留标准：轨迹连续且贴地，阳光和阴影中的明暗一致，颜色不浮在路面上；不出现厚条、接缝和深度闪烁。通过后再将烟雾和胎痕接回已有轮胎遥测，先保持原触发条件。

## 其他候选项是否值得做

| 项目 | 当前优先级 | 判断依据 |
|---|---|---|
| 主画面清晰度与画质降级顺序 | 高 | 直接对应用户看到的整车发糊，也决定新增效果能否保留 |
| 天空亮度与轮胎效果修正 | 高 | 当前有明确观感问题或实现缺口 |
| 局部路面补丁、胎痕、路缘污渍 | 中 | 对近景真实感有针对性；等基础光照和清晰度稳定后少量添加 |
| 阴影更新、AO 档位 | 中至高 | 当前移动时会更新桌面阴影图；可用于减少触发动态降分辨率的压力，收益待实测 |
| 远景 LOD / 合批 | 按瓶颈决定 | 等有明显远景几何或绘制瓶颈再做，不先全场景重构 |
| 局部反射探针 | 后续 | 解决车辆在不同场地区域仍使用同一静态反射的问题；不能修复模型轮廓模糊 |
| 级联阴影 CSM | 后续 | 近车阴影范围约 56 m；远景缺阴影或边界跳变明显时才有明确收益，并增加阴影绘制成本 |
| 整场景体积光 | 暂缓 | 当前晴天下午没有必须依赖它的画面目标；先做好粒子烟雾 |

## 对比和停止标准

只围绕一个保时捷清晰度机位、两个天空朝向、烟雾与胎痕固定样例做检查，不重跑全部六车矩阵。预览保持 5 FPS；性能只对有希望保留的方案做一次短的正常刷新率对照，并记录分辨率、粒子数及 GPU 耗时。若样本波动明显，说明不确定性，不为追求漂亮数字连续重复。

交付同机位天空 A/B、保时捷清晰度对比，以及可单独查看烟雾/胎痕的实机预览。每个小样可以分别保留或撤回，不让一个失败效果牵连整版画面。未实现的新特性不计为完成。

参考：[Three.js Sky](https://threejs.org/docs/pages/Sky.html)、[PointsMaterial](https://threejs.org/docs/pages/PointsMaterial.html)、[Texture 与各向异性过滤](https://threejs.org/docs/pages/Texture.html)、[CSM](https://threejs.org/docs/pages/CSM.html)、[LOD](https://threejs.org/docs/pages/LOD.html)。实施时以项目已安装的 r180 API 为准，当前在线文档的新接口不直接假定可用。
